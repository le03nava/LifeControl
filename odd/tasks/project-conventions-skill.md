## Objective

Add one repo-level `project-conventions` skill that forces compliance with technical and
governance conventions, reduces change risk (security / reliability / operability), and demands
verifiable evidence on every delivery. Wire the governance docs to it and remove the broken
skill references.

## Decisions already made (by the user)

1. **Location: `.agents/skills/`** as the single source of truth. Claude Code is explicitly out of
   scope. Rationale (verified): `.agents/skills/` is read natively by Pi and OpenCode, is the
   documented cross-client convention, and is not gitignored. `.opencode/` and `.pi/` ARE
   gitignored, so skills placed there are invisible to the team.
2. **One skill with dispatch**, not two per-component skills. `references/api.md` and
   `references/angular.md` hold component-specific evidence.
3. **Materialize it** (write the files).
4. **The AGENTS.md files are in scope**: fix the broken references and register the new skill.

## Why one skill with dispatch (evidence)

- Pi and OpenCode walk ancestors UP to the git worktree root and never descend. With the agent
  started at the repo root, `<component>/.agents/skills/` is not discovered at all. Per-component
  location scoping does not work in this monorepo.
- OpenCode requires `name` to equal the containing directory name and, on a duplicate name,
  logs `duplicate skill name` and overwrites under `concurrency: "unbounded"` — a race. Two
  skills named `project-conventions` cannot coexist.
- The Agent Skills specification lists `references/` for exactly this ("Domain-specific files
  (`finance.md`, `legal.md`, etc.)"), loaded on demand.

## Revision 2 — de-duplication and risk gating (post self-review)

Motivation: the first version created a second source of truth. `references/api.md` and
`references/angular.md` asserted version numbers and numeric thresholds that are declared in
`build.gradle`, `check-coverage.mjs`, `angular.json` and `package.json`. Those will rot, and a
stale evidence index manufactures false PASS. The Output Contract also demanded all six blocks
plus 19 controls regardless of risk, which is pure ceremony on a one-line change.

### Fix 1 — the skill carries PROCESS, not FACTS

Invariant: no version number, no numeric threshold, no percentage, and no enumerated dependency
inventory may appear in any skill file. Each such value is replaced by the exact file path that
declares it, plus a stable one-clause statement of what that file governs. Gate commands stay
(they are the contract) but must be attributed to their declaring file. Stable rule names and
capability names may stay; their configuration values may not.

Mechanical check, must return nothing:
`grep -rnE '[0-9]+\.[0-9]+|[0-9]+ ?(kB|MB|%)' .agents/skills/project-conventions/`

### Fix 2 — Output Contract gated by risk

- **low risk** -> exactly three blocks: `Risk Classification`, `Controls Evaluated` (applicable
  rows only), `Gaps Detected` (or `none`). `Required Follow-ups` may be omitted when empty.
- **medium or high risk** -> all six blocks in the mandated order.
- Uncertain risk -> treat as the higher level (fail closed).

### Files touched by Revision 2

`SKILL.md` (Evidence Contract principle + risk-gated Output Contract),
`references/api.md`, `references/angular.md` (assertions -> pointers),
`assets/pr-evidence-template.md` and `assets/convention-checklist.md` (low-risk path),
`assets/security-gates.md` (dependency-coverage wording -> pointer).

## Revision 3 — PR chains and base branches (2026-09-22)

Motivation: the S2 delivery of `product-variant-admin-ui` hit the base-branch deletion trap. Its own
record already carried the rule ("Chain hygiene", retarget before merging), and it was followed by
hand. A rule that lives only in one feature record and one person's memory is not a convention: the
next chain will not read it. This revision moves it into the skill as a gate plus a reference.

### Why it is a gate and not a fifth Hard Rule

The verified Revision 2 invariant pins the Hard Rules count at 4. The chain rule is a
trigger-plus-required-action, which is exactly what the Decision Gates table is for, so it was added
there and the count stays at 4.
