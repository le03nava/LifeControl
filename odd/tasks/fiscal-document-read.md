# ODD feature: fiscal-document-read

**Repository**: LifeControl — `life-control-api` (the `fiscal` module and its controller), `odd/tasks/`
**Branch**: `feat/fiscal-document-read` · **Worktree**: `~/workspace/LifeControl-worktrees/feat-fiscal-document-read`, cut from `origin/main @ c0380c58`
**Status**: implemented — issue **#947**, the contract `#932` is blocked on. Once it lands, a caller who never issued the document can still name it, which is the only way a cancellation — an act taken days later, in another session — is reachable at all. Nothing is deferred; the two limits are stated as limits rather than as future work (the authority's code is not storable, `L4`).
**Created**: 2026-11-17 · **Risk**: item 3 — a new public read contract, and the first read of `fiscal_document` that is not a byte-for-byte artefact. It is additive (no existing endpoint, field or status moves), it is read-only (no write path, no migration, no credential), and the tenant boundary it must respect is the one every fiscal read already goes through.

## Objective

Give a sale's fiscal document a reader. `POST /api/fiscal-documents` answers a `documentId` to the caller who issued it and to nobody else, `SalesOrderResponse` carries no fiscal pointer, and `FiscalDocumentDraft` is returned by no endpoint — so the document could be issued and then lost, while `GET /{id}/xml` and `POST /{id}/cancellation` waited for an id nobody could produce.

## Specs

Quoted from issue **#947**, which is the request. `S1` carries the correction commented on the issue on 2026-11-17 (`L4`).

- **S1** — "`GET /api/fiscal-documents/by-sale/{salesOrderId}` with a `lc-admin` or `lc-sales` caller answers **200** with `documentId`, `salesOrderId`, `status`, `uuidFiscal`, `stampedAt`, `folio` and the cancellation block (`cancellationDocumentId`, `motive`, `cancelledAt`) when one exists." — the stored block, not the ephemeral `statusUuid`/`message`.
- **S2** — "The response answers **204** with no body when the sale has no stamped document, including a sale whose only rows are drafts or refused attempts: never invoiced is a state, not a failure, and a `404` would make every completed sale raise an error toast in a client that treats 404 as one."
- **S3** — "A cancelled document answers **200**, not 204: `V108`'s append-only trigger never updates the stamped row …, the cancellation **inserts** a `CANCELLED` copy naming it, so the sale still has its stamped document and the copy is reported in the cancellation block. A reader that answered 'no document' here would contradict the authority."
- **S4** — "The XML is **not** part of this response; `GET /{id}/xml` remains the only carrier of the stamped bytes."
- **S5** — "A sale that does not exist and a sale of another company both answer **404**, the same answer, so a foreign id is indistinguishable from an absent one."
- **S6** — "A caller holding neither role answers **403**; a `salesOrderId` that is present but not a UUID answers **400** with a message that names the parameter; a path that states no `salesOrderId` at all answers **404**, because it names no resource and must not answer **204**."
- **S7** — "The read is tenant-scoped by the same policy as every other fiscal read: a document of another company is never returned even when its sale id is known."
- **S8** — "`api-gateway` has a route for the path, and `GatewayRouteCoverageTests` passes — a new endpoint without a route is green in the API and a 404 in production."
- **S9** — "The three existing mappings are unchanged and their suites stay green; `./gradlew test` passes."

Non-goals, the issue's own words: listing documents across sales or filtering by status; exposing drafts, refused attempts or the attempt key; the Angular screen (`#932`); the receiver's acceptance window (`#929`); any substitution or re-issue flow after a cancellation.

- **L3** — **both finders already exist, so this unit adds no query.** `findByCompanyIdAndSourceTypeAndSourceIdOrderByCreatedAtAsc` gives every row a sale ever produced and `findByCompanyIdAndCancelsFiscalDocumentId` gives the cancellation copy that names one. The service picks the `STAMPED` row and asks the second finder about it; a sale with no `STAMPED` row answers 204. This is why `T1` is one service and one DTO, not a repository change.
- **L4** — **a criterion of #947 was corrected before any code was written, and the correction is on the issue.** The issue asked the cancellation block for the authority's `statusUuid` and `message`. Measured: `fiscal_document` has no such columns (`V108__fiscal_document.sql:72,100-104`; `V112__fiscal_cancellation_motive.sql:39-44`), and both values are arguments of `FiscalDocumentCancellation.written(...)` (`:69-78`) that nothing persists. A stored answer can state **that** it was cancelled, **which** motive, **when** and **which** document; it cannot state the authority's numeric code without a migration this issue does not include. The replacement criterion is `S1`, and the limit is stated rather than hidden. `#932` is unaffected: its `S4`/`S5` need the code on a refusal (the 409 body carries it) and on the 202 of the call being made (the response carries it).
- **L5** — **the gateway half may already be done.** `Routes.java:70` routes `/api/fiscal-documents/**`, which covers `/by-sale/{id}` by prefix. `T3` proves it with `GatewayRouteCoverageTests` rather than changing the route file for the look of it; if the coverage test enumerates exact paths instead of prefixes, that file gains the path and `T3` says so.
- **L6** — **204 rather than 404 for "never invoiced" is a client contract, not a REST nicety.** `shared/data/error-interceptor.ts:12-27` toasts on every failed request, and `shared/data/http-error-message.ts:11-38` has no 404 exception: a sale that was simply never invoiced would raise a red toast on a screen whose job is to offer the issue action. The 204 makes "not yet" a state the caller renders, which is what `#932`'s `S1` needs.
- **L7** — **the API is its own Gradle build, and the root one does not contain it.** `settings.gradle` at the root includes `api-gateway` **only** (`life-control-api` is absent by design), and the root `gradlew` is not even tracked; the API ships its own wrapper at `life-control-api/gradlew` with its own `settings.gradle` (`rootProject.name = 'life-control-api'`). So the command is `cd life-control-api && ./gradlew test`, and `gradle :life-control-api:test` from the root fails with *project 'life-control-api' not found in root project 'LifeControl'* — a failure that reads like a broken checkout and is not one.
- **L8** — **`created_at` had to be read back, and the spec did not say so.** The cancellation block's `cancelledAt` is `fiscal_document.created_at`, a column the schema fills with `now()` and the entity maps `insertable = false, updatable = false` — so an instance the **same transaction** inserted never carried it and the first-level cache hands that instance back instead of the row the database wrote (`getCreatedAt()` is `null` on a `NOT NULL` column). The read is `SELECT`-only in production, where the cancellation is always a different transaction, so this is not a production defect; it is what a same-transaction read like the suite's would answer. The service therefore refreshes the row when the value is missing, which is the tree's own idiom for a schema-stated column (`FiscalDocumentStamper#refreshStatementFacts`, `PurchaseOrderService#refreshDerived*`), and it does so only in that case. The alternative — `@Generated(event = INSERT)` on the entity — would have changed the insert path of every writer to fix one reader, and this unit owns neither.
- **L9** — **the gateway half needed no change, confirmed rather than assumed.** `GatewayRouteCoverageTests` compares **first segments** (`/api/fiscal-documents`), not exact paths, so `/by-sale/{salesOrderId}` is covered by `Routes.java:70` and the suite passes without touching the route file — `L5`'s second outcome, measured.
- **L10** — **the independent verification of 2026-11-17 met six verdicts and failed one clause, and the clause was the record's, not the code's.** Met on the response: `S1`, `S2`, `S3`, `S4`, `S5` and `S7`; `S8` and `S9` were already measured (`L9`). The failing clause was `S6`'s *"a missing, blank or malformed `salesOrderId` answers **400**"*: a value that is **present** but not a UUID is a 400 whose message names the parameter (`GlobalExceptionHandler.java:148` — now asserted, not inferred from the status), while a path stating **no** `salesOrderId` (`/api/fiscal-documents/by-sale/`) matches no mapping and answers **404**. A 400 there would claim the request stated an invalid value when it stated none, and the answer must not be the **204** of "never invoiced" either, so `S6` is rewritten to the three answers the shape actually has. **Three probes the verification proved were missing are now in the suite**: `folio` is asserted `null` on a stamped document (`S1` names the field and nothing looked at it), a foreign sale with **no** document asserts **404** and not 204 — the `S2`/`S5` boundary, which fails if the read ever looks at fiscal rows before the sale — and the malformed-id case asserts the message instead of a bare status. **The `entityManager.refresh` branch is gone** (`FiscalDocumentReadService#asCancellation`): it was unreachable in production, where a read is one request and one transaction, and a refresh from a `@Transactional(readOnly = true)` read that joined an outer **write** transaction would silently discard that transaction's pending changes; the cancelled case now flushes and clears the row it wrote, so the read loads the committed row and `$.cancellation.cancelledAt` is still asserted — the crutch is replaced by the caller that owns the write. **`FiscalDocumentRead.Cancellation.cancelledDocumentId` is renamed `cancellationDocumentId`**, because it holds the **cancellation row's** id while `FiscalDocumentCancellation.cancelledDocumentId` — same module — holds the **cancelled document's** id; `S1` is corrected to the new name and the component's javadoc states both ends of the pointer. **The controller's class javadoc states the restriction again**: one read by sale exists, and there is still no list across sales, no substitution, no re-issue and no drafting surface — the diff had deleted that sentence and left only its non-goal list.
